Сводка результатов

Эксперимент проверяет, можно ли улучшить поведение агента на GAIA за счёт дополнительного compute на этапе inference: Best-of-N, голосование, judge/верификация, управление контекстом и budget-aware техники. Текущий setup: GAIA Level 1, 53 задания, небольшая модель Qwen 3.5 9B и запуск через инфраструктуру проекта.

Baseline

Baseline был посчитан на всех 53 задачах GAIA Level 1. Средняя точность составила 0.453, среднее время выполнения — 4.5 минуты на задачу, среднее потребление — 509k токенов на задачу.

Сравнение техник

Сравнение показывает, что не все test-time техники дают одинаковый эффект. Лучшие приросты accuracy дали BUDGET_TRACKER, VOI, HIAGENT, STRUCTURED_NOTES и BAVT. Нейтральными оказались SHORT_MAK и ACON. Часть техник снизила accuracy относительно baseline: ADAPTIVE_BON, CONTEXT_COMPACTION, SELF_CONSISTENCY, RESUM и RANKED_VOTING.

Стоимость

Стоимость сравнивалась по двум осям: время на задачу и token usage. Baseline mean: 4.5 минуты и 509k токенов на задачу. По среднему времени дешевле baseline оказались ACON, SHORT_MAK, HIAGENT и STRUCTURED_NOTES. По токенам ниже baseline оказались RESUM и VOI, а STRUCTURED_NOTES осталась практически на уровне baseline.

Реальное потребление

Квадрант эффективности показывает trade-off между accuracy delta и overhead. STRUCTURED_NOTES выглядит как наиболее удачная lightweight-техника: она даёт положительный прирост accuracy и при этом не требует дополнительного token/time budget относительно baseline. HIAGENT также даёт прирост при низком overhead. BUDGET_TRACKER даёт максимальный прирост, но требует дополнительного compute.

Budget Tracker

Отдельный график показывает метрики BUDGET_TRACKER: success per task, cumulative tokens, max effective input tokens, долю context window и рабочее время. Во втором и третьем графиках пунктирные линии отмечают context window используемой модели: baseline 256k и BUDGET_TRACKER 128k.

Проделанная работа

Для локального запуска был собран отдельный файл localModel.sh. Были добавлены ограничения на количество использования tool и время работы tool, потому что Qwen использовал очень много вызовов. Интерактивный sudo внутри tool calls был запрещён.

Отдельно зафиксированы операционные риски: зависающие tool/python-процессы, избыточное количество tool calls и нестабильность отдельных InspectAI tools при высоком потреблении памяти.

Ограничения

  • Недостаточно вычислительных мощностей.
  • Проверялись простые задачи GAIA Level 1.
  • Использовалась маленькая единственная модель Qwen 3.5 9B.
  • Несмотря на широту задач, рассматривается один датасет.
  • Статистическая значимость без Level 2 остаётся неясной.

Выводы

Подбор техник может дать прирост точности на benchmark loop. Это означает, что реальные оценки scaling laws для агентного inference могут быть систематически занижены относительно таймлайнов: если оценивать только наивное масштабирование, можно недооценить будущие возможности моделей.

  • BUDGET_TRACKER показал максимальный прирост accuracy: +0.14.
  • VOI дал +0.10 accuracy, но требует аккуратного учёта time overhead.
  • STRUCTURED_NOTES выглядит особенно практично: +0.06 accuracy при снижении среднего времени и token usage около baseline.
  • Наивные техники вроде SELF_CONSISTENCY и RANKED_VOTING в текущем setup могут ухудшать результат.
  • Дальше планируется проверять комбинации техник, подготовить пост на LessWrong и выделить инфраструктуру в reusable/open-source компоненты: gaia-experiment-launcher и tts-proxy-framework.
