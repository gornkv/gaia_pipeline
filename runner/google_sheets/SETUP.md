# Настройка общего плана Google Sheets

`Code.js` — рабочий исходный код Web API, а `appsscript.json` — его манифест.
Их можно публиковать: они не содержат аккаунтов, адресов таблиц или секретов.
Каждый владелец разворачивает собственную копию под своим Google-аккаунтом.
Worker обращается к API по URL с общим секретом, Google-вход коллегам не требуется.

## Развёртывание через браузер

1. Создайте таблицу или откройте существующую, доступную вам на редактирование.
2. Создайте проект на https://script.google.com и вставьте `Code.js` в редактор.
3. В настройках проекта включите отображение `appsscript.json` и скопируйте манифест.
4. В «Настройки проекта → Свойства скрипта» добавьте:
   - `SPREADSHEET_ID` — часть ссылки между `/d/` и `/edit`;
   - `SHEET_ID` — число из `gid` в ссылке на нужную вкладку, по умолчанию `0`.
5. В редакторе выберите функцию `setup`, нажмите «Выполнить» и подтвердите разрешения.
   Пустая шапка создастся автоматически. Непустая неподходящая шапка вызовет ошибку.
6. В свойствах скрипта появится `PLAN_GOOGLE_SHEETS_TOKEN`. Сохраните его локально
   в `.env`; в репозиторий этот файл не попадает. Повторный `setup` сохраняет секрет.
7. Создайте развёртывание типа «Веб-приложение»: выполнение от вашего имени,
   доступ «Все», включая пользователей без входа в Google. Организационная политика
   Google Workspace может запрещать этот вариант доступа.
8. Скопируйте опубликованный URL, заканчивающийся на `/exec`.

В локальном `.env` worker задайте:

```dotenv
PLAN=https://docs.google.com/spreadsheets/d/YOUR_SPREADSHEET_ID/edit
PLAN_API_URL=https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID/exec
PLAN_GOOGLE_SHEETS_TOKEN=YOUR_SECRET
```

API работает с таблицей и вкладкой из свойств скрипта. Ссылка `PLAN` сама по себе
не переключает таблицу на сервере. Также можно задать в `PLAN` непосредственно
URL `/exec`, тогда `PLAN_API_URL` не нужен.

Все worker одного плана должны использовать один Apps Script проект: его
серверная блокировка распределяет задачи между машинами. Блокировка не запрещает
ручные правки людей; не сортируйте и не удаляйте строки в момент записи результатов.
Для просмотра используйте представления фильтров. Идентификаторы `job_id` должны
быть уникальными, а служебные поля выполняющихся задач нельзя редактировать вручную.

## Работа через CLI

Для владельца, который хочет загружать исходники из репозитория:

```bash
npm install -g @google/clasp
clasp login
```

Включите Apps Script API на https://script.google.com/home/usersettings под тем же
аккаунтом. Создайте новый локальный каталог вне репозитория, выполните там
`clasp create --type standalone --title 'Shared plan API'`, затем скопируйте туда
`Code.js` и `appsscript.json`. Выполните `clasp push --force`, настройте свойства
и запустите `setup` в браузере, затем выполните `clasp deploy`.
При последующих обновлениях используйте ID собственного развёртывания.

## Доступ и публикация

Свойства скрипта находятся в Google и не включаются в эти исходники.
Не публикуйте `.clasprc.json` с OAuth-токенами, `.env` и общий секрет.
`.clasp.json` содержит привязку к вашему Script ID; он тоже исключён из Git.
Не публикуйте личные ссылки на таблицы и API, если не хотите раскрывать эти ресурсы.

`executeAs: USER_DEPLOYING` в манифесте означает аккаунт того, кто разворачивает
свою копию; это не привязка к автору репозитория. Google может показывать сведения
о владельце в интерфейсах авторизации и доступа: эти исходники не обеспечивают
анонимность уже опубликованного приложения. Для публичного сервиса используйте
отдельный рабочий Google-аккаунт.

Отзывать доступ отдельного коллеги при общем секрете нельзя: для отзыва замените
`PLAN_GOOGLE_SHEETS_TOKEN` в свойствах и передайте новое значение остальным.
